## 2026-10-31 follow-up: second-chat capture fix

- The screenshot supplied after the 0.1.1 test showed a recognized second Codex chat, collection enabled, and zero events. That chat had not yet been confirmed to have a trusted, post-enable lifecycle hook invocation. The screenshot also correctly showed that 0.1.1 did not collect message/tool content or token usage.
- Root cause addressed in 0.1.2: the old command-hook path keyed capture from hook `session_id`, while the UI opt-in key came from Codex MCP `threadId` metadata. Those identifiers were not bridged, so a valid event could be silently written under a different key.
- The new `UserPromptSubmit` hook calls the already-connected `session_lens.record_prompt_submit` MCP tool with an empty input. Codex's [MCP hook executor](https://github.com/openai/codex/blob/main/codex-rs/core/src/hook_mcp_executor.rs) attaches the owning thread ID to tool-call metadata; the server uses that same value as `set_collection`, and does not accept or persist prompt content. The public [Hooks guide](https://learn.chatgpt.com/docs/hooks) confirms MCP hooks use an existing MCP connection and require review/trust like command hooks.
- Updated both portable and Codex compatibility manifests to `0.1.2-l0`, rebuilt the sanitized package, and replaced the local plugin cache. `codex plugin add` installed `0.1.2-l0`; the cache contains the built server/UI and manifests but no source, test, dependency, or Git directories.
- Fresh verification: `pnpm package:local` passed TypeScript/build, 61 tests across 9 files, and stdio smoke. The smoke confirms two synthetic thread contexts remain isolated and the event refreshes through the MCP protocol. This does not verify Codex desktop hook trust or invocation.
- User follow-up on 2026-10-31: no message had been sent after enabling capture, and `/hooks` showed no entry or “not installed” in the desktop context. That explains the empty count and means the screenshot was not a post-hook-trigger test. The updated package is installed in the local CLI profile; the desktop still needs to reload it and expose the hook for review.
- Remaining desktop acceptance: restart/reload Codex so the new hook definition is loaded; review and trust the Session Lens `UserPromptSubmit` hook in Codex; open the panel and enable capture separately in two chats; send one harmless message in each; refresh and confirm each chat shows its own event only. Token usage remains unavailable in L0 and is a separate unmet L0 gate.
